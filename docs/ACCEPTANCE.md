# Соответствие заданию

Основание: [README организаторов](https://github.com/BCC-HUB/ai-requirements-validator-task/blob/main/README.md).

| Обязательство | Реализация | Как проверить |
|---|---|---|
| Чтение документа | PDF с текстом, MD, TXT | CLI с путём входа |
| Обращение к LLM | Gemini REST / Ollama chat | Живой режим, metadata.calls |
| Выделение требований | Inventory с original_id, цитатой, координатами | Реестр отчёта |
| Проверка каждого | Assessment с четырьмя измерениями | Полное совпадение ID реестра и оценок |
| Проверка набора | Межраздельные замечания и set_assessment | Раздел отчёта |
| Русский отчёт | Markdown + HTML + JSON | Файлы по output path |
| Паспорт | Дата Asia/Almaty, модель, версия, хеш | Metadata |
| Сводка и приоритет | Поддержанные, критичные/высокие, уточнения | Детерминированный подсчёт |
| Воспроизводимый запуск | pyproject, uv.lock, .env.example | uv sync --frozen |

Критерии ясности, полноты, проверяемости, атомарности и согласованности используются как практическая методика. Мы не объявляем полную реализацию всех пунктов ISO/IEC/IEEE 29148 и IEEE 830.

## Правила подсчёта

Требование — атомарная запись реестра. Один пункт источника может дать несколько записей. Замечание — один finding, в том числе конфликт нескольких требований. В итоговое число подтверждённых модельным ревью замечаний входят только supported. Уточнения и отклонения показаны отдельно. «Поддержано» не означает независимое подтверждение человеком.

## Риск перед сдачей

Нужен отчёт реального агента по документу организаторов. `examples/demo-report.*` не подходят: это синтетическая тестовая фикстура. Обязательна ручная проверка полноты реестра, важнейших дефектов и соответствия формальных интерпретаций источнику. Отчёт не редактируется для имитации результата запуска.

## Порог готовности

Высокие/критичные поддержанные замечания означают необходимость исправлений до реализации. Уточнения означают необходимость решения аналитика. Отсутствие обнаруженных дефектов не означает доказанную готовность документа.
